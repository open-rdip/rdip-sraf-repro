# N3 — frontier-model extraction and the robustness re-run

**Status:** pipeline built, not yet run. Budget armed, no spend recorded.
**Target:** the journal extension, section 7. Due with the draft on 30 Nov 2026.

## What this task is for

The published extraction benchmark reports an entity-level F1 of about 0.27 on
the gold tier, from three quantised open-weight models. The obvious objection is
that the number measures the extractor rather than the artifacts. N3 answers it
by running hosted frontier models over the same corpus, under the same prompt
and the same retrieval configuration, and then re-running the Phase 4 validity
analysis with whichever extractor scores best.

The outcome is pre-committed in both directions. If a frontier model scores much
higher, the claim that the information is missing from the repositories weakens
to a claim that the extractor was weak. That must be reported, not avoided. With
the robustness re-run attached, either result is publishable.

## The model set

Declared in `rag_pipeline/model_registry.py`, not in a submission command.

| key | backend | scope | est. | role |
|---|---|---|---:|---|
| `gemini-flash` | google | corpus | $2.52 | **contaminated**, reported apart |
| `grok` | xai | corpus | $5.00 | uncontaminated |
| `gpt5` | openai | corpus | $5.80 | uncontaminated |
| `sonnet` | anthropic | corpus | $6.71 | uncontaminated |
| `opus` | anthropic | **gold only** | $1.68 | ceiling probe |
| | | **total** | **$21.70** | against a $35 cap |

Two of these choices carry an argument.

**Gemini is contaminated and is still run.** The ground-truth candidates were
generated by that family, so a Gemini model is scored partly against its own
family's annotation. Excluding it would discard information; a higher score
quantifies the contamination rather than hiding it. It is run, reported in a
separate row, labelled, and excluded from the headline comparison and from the
choice of best model.

**Opus runs on the gold tier only.** At $4/$20 per million tokens a corpus pass
costs $13.42, which the budget cannot carry alongside the other four. The gold
tier is the tier its result would be read against anyway, so the probe answers
"how much headroom is there above the best corpus model" for $1.68 instead.

## Cost assumptions, and where they bite

The $21.70 is rederivable rather than asserted. One call per deduplicated
retrieved chunk, six fixed queries times three chunks deduplicating to about
fifteen per study, 400-word chunks at roughly 530 tokens plus about 300 tokens
of prompt template, and a single JSON object back:

```
CALLS_PER_STUDY            = 15
PROMPT_TOKENS_PER_CALL     = 845
COMPLETION_TOKENS_PER_CALL = 297
```

`tests/test_model_registry.py::test_plan_fits_the_budget` fails if the declared
plan ever stops fitting the declared budget, which is how a silent price change
gets caught.

> **The sensitivity to watch.** The prompt figure is the one that moves. Raising
> chunk size or `top_k` raises it proportionally. There is about $13 of headroom,
> so roughly a doubling of prompt size takes the sweep over budget. The spend cap
> catches that at the moment it happens; the preflight estimate will not, because
> it uses the declared assumptions rather than the live configuration.

## Running it

### 0. Load the keys into the shell first

`config.py` does **not** read `.env` by itself. `cluster/n3_frontier.sbatch`
sources it (`set -a; . "$REPO_ROOT/.env"; set +a`), so the full sweep in step 3
picks the keys up, but steps 1 and 2 below run Python directly and will report
every credential as `NOT SET` even when `.env` is correctly filled. Source it
once per shell:

```bash
cd "$REPO_ROOT"
set -a; . ./.env; set +a
```

Verified on 9 Nov 2026: a bare shell reports `NOT READY` for all five models
with a complete `.env` present. The preflight is right and the shell is wrong.

### 1. Preflight, always, before anything else

```bash
python -m rag_pipeline.n3_preflight
```

Checks four things: a credential exists for every selected model, the provider
accepts the model id **right now**, the prices load into the meter so the cap is
armed, and the estimate fits the remaining budget. The live probe is one short
completion per model, costing a fraction of a cent.

> **Model ids are the known failure.** Provider identifiers change. The ids in
> the registry are the ones the cost plan was built on, each overridable by
> environment variable (`SRAF_N3_GPT_MODEL` and so on). Do not trust the registry
> as a record of what exists today. Trust the preflight, which fails loudly and
> cheaply on a wrong id instead of several hundred paid calls into a pass.

An unpriced model is the quiet failure: the meter counts its tokens but cannot
charge them, so the cap stops protecting. `seed_prices` runs before the first
call and the preflight reports any model it could not price.

### 2. Smoke test three studies on one model

```bash
python -m rag_pipeline.run_n3_frontier --models grok --limit 3 --no-rerun
```

(Same shell as step 1, or source `.env` again.)

Confirms the whole path end to end — retrieval, extraction, mapping, triples,
metering — for under a dollar.

### 3. The full sweep

```bash
sbatch --export=ALL cluster/n3_frontier.sbatch
```

**Choosing the model order.** `SRAF_N3_MODELS` is a comma-separated list and
`resolve()` preserves the order given, so it controls the sweep order as well as
the selection. Do **not** pass it inside `--export`: Slurm parses that option as
a comma-separated list of assignments, so
`--export=ALL,SRAF_N3_MODELS=grok,gpt5,sonnet` sets `SRAF_N3_MODELS=grok` and
then tries to export `gpt5` and `sonnet` as variables of their own. Export it in
the shell instead and let `--export=ALL` carry it:

```bash
export SRAF_N3_MODELS=grok,gpt5,sonnet,opus,gemini-flash
sbatch --export=ALL cluster/n3_frontier.sbatch
```

That order is deliberate. The headline claim rests on the three uncontaminated
corpus models, so they run first; `opus` is a gold-tier ceiling probe and
`gemini-flash` is reported separately because of the contamination, so losing
either to a mid-sweep failure costs least.

Resume is per `(study, model)`, so a re-submission skips completed work. The
meter persists across jobs, so a resumed run continues counting rather than
starting the budget over. `BudgetExceeded` aborts the **entire sweep**, not just
the current model, because continuing into the next model with the cap already
breached is exactly what the cap exists to prevent.

### 4. The re-run, which is the actual point

Steps 3 to 5 of the driver run automatically after extraction, or on their own:

```bash
python -m rag_pipeline.run_n3_frontier --rerun-only
```

- scores every discovered model against the ground truth (`compare_models`)
- names the best **uncontaminated corpus** model (excludes Gemini and Opus)
- re-runs `analysis.criterion_validity`, which is N1

Then compare the output against the committed `analysis/criterion_validity.md`
and **report both**, whichever way it goes.
